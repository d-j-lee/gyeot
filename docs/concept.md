# 곁 — 개념

> 곁은 사람의 주의를 지키는 동료다. 여러 AI 세션이 사람을 기다리는 순간을 놓치지 않게 하되, 그 대가로 집중을 깨지 않는다.

## 1. 문제

생태계의 기계 쪽은 이미 단단하다. `~/.claude` 체계, 기계적 훅, fsmap·AOK 하네스 게이트, AOK 원장과 관제실, work-atlas의 맥락이 있다. 병목은 사람과 맞닿는 접점이다.

- **"당신 차례"가 흩어져 있다.** 클라우드 세션은 AOK 관제실이 본다. 로컬 Windows CLI 세션과 Codex는 아무도 모아 주지 않는다. DocBench "볼 것"과 dj-assis 브리핑까지 더하면 사람을 부르는 곳이 넷이다. AOK D18은 이미 "인박스는 하나로"라고 적어 두었다.
- **기다림을 놓친다.** 터미널 벨 하나로는 다른 창에서 일하는 동안 세션이 20분째 승인을 기다리는 걸 알 수 없다. 에이전트가 많을수록 사람의 응답 지연이 전체 처리량의 상한이 된다.
- **알림을 늘리면 집중이 깨진다.** dj-assis 시험 01에서 하던 일 중에 띄운 브리핑은 전부 "이번 작업에 집중"으로 넘겨졌다(D-013). 많이 알리는 비서는 실패한다.

곁은 이 셋을 한 번에 다룬다. 흩어진 신호를 한곳에 모으고, 지금 사람을 불러야 하는지를 판단하고, 부를 때는 가장 덜 방해하는 방식을 고른다.

## 2. 곁이 하는 일

1. **듣는다.** Claude Code·Codex 훅, 하네스 로그, channel 연결을 한 이벤트 흐름으로 모은다. 훅은 절대 작업을 막거나 기다리게 하지 않는다.
2. **판단한다.** AOK 관제실과 같은 이름·점수 체계로 "당신 차례" 항목을 만든다. 승인 대기 95, 결정 85, 실패 80, 안 읽은 결과 55, 그리고 대기 가산과 감쇠까지 같다. 숫자는 규칙이 계산하고, LLM은 판단에 끼지 않는다.
3. **표정으로 먼저 알린다.** 아바타의 표정과 새싹 색이 상태를 보여 준다. 주변 시야로 "지금 나를 기다리는 게 있다"를 알 수 있으면 말할 필요가 없다.
4. **말은 아껴서 한다.** 말풍선과 소리는 예산 안에서만 쓴다. 집중 모드와 조용한 시간을 지키고, 사람이 이미 그 세션에 있으면 침묵한다. 모든 알림에는 "왜?"가 붙는다.
5. **대화를 잇는다.** channel을 통해 사람이 곁에게 한 말이 실행 중인 Claude Code 세션에 그대로 들어가고, Claude의 답은 곁이 읽어 준다. Claude는 곁을 통해 선택지 카드를 내밀 수 있다.
6. **배우되 스스로 바꾸지 않는다.** 자주 넘기는 종류가 보이면 "이건 앞으로 표정으로만 알릴까요?"라고 제안한다. 사람이 받아들일 때만 바뀐다.

## 3. 계승한 원칙

곁은 새 규칙을 만들기보다 이미 검증된 결정을 지킨다.

| 원칙 | 출처 | 곁에서 |
|---|---|---|
| 권한 승인·병합·삭제는 대신하지 않는다 | dj-assis D-009, AOK 관제탑 v2 | 승인 카드에 승인 버튼이 없다. channel의 권한 중계 capability도 선언하지 않는다 |
| 비서가 먼저 브리핑을 띄우지 않는다. "지금은 넘기기"는 언제나 정답 | dj-assis D-013 | 브리핑은 부를 때만 나온다. 모든 말풍선에 넘기기가 있다 |
| 음성은 헤드라인, 화면은 증거 | dj-assis P5 | 첫 줄만 읽고, 근거는 카드에 둔다 |
| 플랫폼이 주는 인프라는 다시 만들지 않는다 | dj-assis concept §4 | 받아쓰기는 Windows Win+H, 음성은 Windows 한국어 음성(speechSynthesis) |
| 같은 점수 체계, 인박스는 하나로 | AOK dashboard §3a, D18 | kind 이름·점수·대기 가산·감쇠를 그대로 쓴다 |
| 무시 기록은 임계 조정을 제안하는 데만 쓴다 | AOK dashboard §3a | 학습 결과는 제안으로만 나온다 |
| 숫자는 계산이 내고 LLM은 말만 한다 | work-atlas 규칙 | 점수·전달 판단은 결정적 코어가 한다 |
| 훅은 네트워크를 기다리지 않는다. 언제나 exit 0 | agent-office, fsmap | 훅 심은 400ms 안에 보내고, 못 보내면 스풀에 쓰고 끝낸다 |
| 사용자에게 가는 말은 한국어 | dj-assis architecture §6 | UI·말풍선·음성 모두 한국어 |

## 4. 목표 · 비목표 · 안티골

**목표**
- 로컬 Windows의 모든 Claude Code·Codex 세션의 "당신 차례"를 한곳에서 본다.
- 승인·결정을 기다리는 시간을 줄인다. 집중을 깨는 횟수는 늘리지 않는다.
- 아바타와 대화하듯 실행 중인 세션에 말을 걸고, 답을 듣는다.
- 모든 판단을 설명할 수 있다("왜 지금 알렸나").

**비목표 (v0.1)**
- 클라우드 세션 직접 관제. AOK 관제실의 일이다. 곁은 같은 점수 코어를 나눠 쓰는 쪽으로 간다(로드맵).
- 작업 위임·세션 생성 오케스트레이션. AOK 허브와 dj-assis 데스크의 일이다.
- 폰. 폰 쪽 표면은 dj-assis가 맡는다.

**안티골 — 이렇게 되면 기술적으로 돌아가도 실패다**
- 네 번째 인박스가 된다.
- 클리피가 된다. 묻지 않은 조언을 하고, 맥락 없이 끼어든다.
- 사람 대신 승인을 누르거나, 누르기 쉽게 만들어 승인의 무게를 덜어 낸다.
- 귀엽기만 하고 쓸모가 없다. 표정이 정보를 담지 않는다.
- 스스로 설정을 바꾼다.

## 5. 성공의 기준 (측정 계획)

이벤트 로그(`events/*.jsonl`)만으로 계산할 수 있게 정의했다. 2주 쓰고 잰다.

| 지표 | 정의 | 바라는 방향 |
|---|---|---|
| 승인 대기 시간 | `waiting_permission`부터 그 세션의 다음 `activity`·`prompt`까지, 중앙값·P90 | 줄어든다 |
| 결정 대기 시간 | `decision` 항목이 열려 닫힐 때까지 | 줄어든다 |
| 말풍선 수용률 | `nudge`·`interrupt` 뒤 2분 안에 그 항목이 처리되거나 그 세션에 `prompt`가 온 비율 | 높다(0.5 이상) |
| 넘기기율 | 전달 가운데 `dismiss` 비율, 종류별 | 낮다. 높은 종류는 제안으로 조용해진다 |
| 끼어듦 | 하루 `interrupt` 수 | 적다(예산 상한 안) |
| 놓친 차례 | 사람이 다른 세션에서 일하는 동안 30분 넘게 열려 있던 blocking 항목 수 | 0에 가깝다 |

## 6. 이름

"곁"은 '가까이 있는 자리'라는 뜻이다. 앞에 나서지 않고 옆에 있다가 필요할 때 손을 드는 동료를 뜻한다. 아바타는 조약돌 모양 몸에 새싹 하나를 단 오리지널 캐릭터다(`docs/avatar-spec.md`). 새싹 색이 상태다.
